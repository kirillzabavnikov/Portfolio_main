# Портфолио Кирилла Забавникова

Next.js App Router, TypeScript, Tailwind CSS и Markdown. Материалы импортированы из публичного Notion. Постоянная синхронизация, CMS и база данных не нужны. Изображения хранятся локально.

## Запуск на Windows

1. Установите Node.js LTS версии 22.10 или новее с https://nodejs.org/.
2. Откройте папку проекта в проводнике, в адресной строке введите `powershell`, нажмите Enter.
3. Выполните команды ниже, откройте http://localhost:3000.
4. Для остановки нажмите Ctrl+C в PowerShell.

```powershell
npm ci
npm run dev
```

Для редактирования удобно использовать VS Code.

## Где что менять

| Что | Файл или папка |
| --- | --- |
| Имя, вступление, контакты, ссылки | `content/site.json` |
| Короткие кейсы Website | `content/projects/*.md` |
| Полные исходники Original | `content/original/*.md` и `*.json` |
| Исходные изображения | `content/original/images/` |
| Оптимизированные изображения | `public/images/` |
| Размеры изображений | `content/assets.json` |
| Цвета, шрифты, размеры, отступы, анимации | `app/tokens.css` |
| Анализ и проверки | `research/ANALYSIS.md`, `research/QA.md` |

В JSON используйте двойные кавычки вокруг текста, запятые между полями, без запятой после последнего. Контакты читаются всеми страницами из одного файла.

## Редактирование и порядок кейсов

В начале каждого Markdown-файла между строками `---` находятся настройки:

```yaml
title: "Название проекта"
slug: project-name
description: "Краткое описание для главной и начала кейса"
cover: my-cover
coverAlt: "Что показано на обложке"
order: 1
published: true
category: "Т-Банк · Супермаркеты"
sourceId: notion-page-id
```

Меньшее число `order` поднимает карточку выше. `published: false` скрывает проект вместе со страницей и ссылками на него. Для удаления удалите Markdown-файл. После следующей сборки список обновится.

Чтобы карточка открывала полный кейс в Notion, добавьте `caseUrl` с его HTTPS-ссылкой. Без этого поля открывается страница проекта на сайте. Для собственного текста превью можно добавить `preview` — строку Markdown, включая ссылки; она заменит стандартную подпись карточки. Полный текст кейса и его `description` при этом редактируются отдельно.

`slug` — адрес страницы. Используйте уникальные латинские строчные буквы, цифры и дефисы. Не меняйте опубликованный адрес без необходимости. Поле `year` необязательное: добавляйте год только если он подтверждён.

После второй строки `---` идёт основной текст:

```markdown
Вступление.

## Задача

Проблема, личный вклад и **подтверждённый результат**.

![Описание первого экрана](/images/screen-one.webp)
![Описание второго экрана](/images/screen-two.webp)

## Результат

Короткое описание. Цели и гипотезы обозначайте отдельно от результатов.
```

Изображения в одном абзаце размещаются рядом. Пустая строка начинает следующую группу. Тексты React-компонентов менять не нужно.

Предлоги и короткие союзы автоматически связываются со следующим словом неразрывным пробелом на главной и в кейсах. В JSON и Markdown можно продолжать писать обычные пробелы. Правило хранится в `lib/typography.ts`; адреса ссылок и программный код оно не меняет.

У текущих кейсов обложка собрана из реальных экранов. Список задаётся дополнительным полем в настройках:

```yaml
coverScreens:
  - image: my-first-screen
    alt: "Описание первого экрана"
  - image: my-second-screen
    alt: "Описание второго экрана"
```

Здесь `image` — имя WebP-файла без расширения, зарегистрированное в `content/assets.json`. Для готовой горизонтальной обложки удалите блок `coverScreens` и укажите файл в `cover`. Поле `cover` также определяет картинку для Open Graph.

## Новый кейс и изображения

1. Скопируйте любой файл из `content/projects/`, задайте другое имя файла.
2. Измените название, `slug`, описание, обложку, порядок и `sourceId` (ID исходной страницы Notion).
3. Сохраните полный текст в Original, сокращённый — в новом файле Website.
4. Положите изображения в `public/images/`. Используйте WebP шириной до 1800 px. Финальные интерфейсы не обрезайте.
5. Для обложки `my-cover.webp` укажите `cover: my-cover`. В `content/assets.json` добавьте размеры:

```json
"my-cover": { "path": "/images/my-cover.webp", "width": 1600, "height": 900 }
```

Добавляйте запись внутрь существующих фигурных скобок, отделяя запятой от соседней. Аналогично укажите размеры иллюстраций: это предотвращает скачки страницы при загрузке. Новая карточка, страница и навигация появятся автоматически.

Для замены картинки замените файл или измените путь в Markdown. Для обложки поменяйте `cover` и `coverAlt`; при изменении пропорций обновите размеры в `content/assets.json`. Не используйте временные ссылки Notion на опубликованном сайте.

## Цвета и шрифты

Параметры подписаны в `app/tokens.css`: `--accent` — цвет ссылок главной, `--background` — фон, `--section-gap` — расстояние между проектами. Внутренние страницы имеют параметры `--case-*`, как в референсе.

На всём сайте используется Inter Variable с поддержкой кириллицы; шрифт поставляется вместе с проектом. Шрифт задаётся в `--font`. Для системного Arial поменяйте значение на `Arial, sans-serif`. Для собственного шрифта положите WOFF2 в `public/fonts/`, добавьте `@font-face` в `tokens.css`, укажите имя шрифта в `--font`.

## Production build

```powershell
npm run typecheck
npm run lint
npm run build
```

Готовый статический сайт находится в `out/`. Для локальной проверки production-версии выполните `npx serve out` и откройте напечатанный адрес. `npm start` для статического экспорта не используется.

## Публикация на Vercel

1. Загрузите проект в свой GitHub-репозиторий. `node_modules`, `.next` и `out` уже исключены через `.gitignore`.
2. В Vercel выберите **Add New → Project** и подключите репозиторий.
3. Выберите Next.js, команда сборки `npm run build`. Переменные окружения не нужны.
4. В `content/site.json` замените `siteUrl` на ваш адрес Vercel или собственный домен для правильных Open Graph и canonical URL.
5. Нажмите Deploy. Последующие изменения основной ветки будут публиковаться автоматически.

В этой работе также используется Sites. Его идентификатор находится в `.openai/hosting.json`; это не секрет. На сборку Vercel файл не влияет.

## Обновления в будущем

Сохраните полный обновлённый текст в Original, затем отредактируйте Website. Проверьте, что метрики подтверждены и не являются целевыми значениями. Выполните проверки, сборку и отправьте изменения в GitHub. Повторный импорт всего Notion не нужен.

Скрипты `scripts/import-notion.py`, `scripts/prepare-content.py`, `scripts/import-images.py` оставлены для воспроизводимости первичного импорта. Нужны Python и Pillow; для обычного запуска сайта они не используются. Импорт изображений требует сетевого доступа к `www.notion.so` и `file.notion.so`. Токены авторизации не нужны.

В этой работе файлы получены из пяти RAR-архивов пользователя: 26 оригинальных экранов. Их локальные копии находятся в `content/original/images/`, соответствие исходным именам — в `content/original/export-map.json`. Сайт работает без доступа к Notion. `scripts/import-export.py` выполняет локальный импорт из `content/export/`; эта папка временная, исключена из Git. В опубликованном исходном проекте все необходимые оригиналы уже сохранены.

## Основные компоненты

- `Navigation` — мобильное меню, Escape и управление фокусом.
- `ProjectCard` — обложка и краткое описание.
- `ProjectVisual` — горизонтальная композиция из реальных экранов или готовая обложка.
- `Contact` — единый блок контактов.
- `lib/content.ts` — загрузка Markdown, проверка метаданных, сортировка и HTML.
- `app/projects/[slug]/page.tsx` — универсальная страница кейса, метаданные и следующий проект.
